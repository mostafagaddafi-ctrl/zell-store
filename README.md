# ZELL — متجر أفلام الزجاج بالمتر

متجر إلكتروني لبيع أفلام حماية وعزل الزجاج للبيوت والشقق **بالمتر الطولي**.
الدفع عند الاستلام، والتوصيل لكل محافظات مصر.

ثلاث خامات: عازل حرارة · مصنفر (خصوصية) · فاميه أسود.

---

## ⚠️ الحالة الحالية

| | |
| --- | --- |
| المتجر | 🟢 منشور على Vercel |
| **إنشاء الطلب** | 🔴 **معطّل** — زرار التأكيد موقوف عن قصد |
| مصدر البيانات | 🟡 كتالوج مجمّد في الكود، **مش الداتابيز** |
| الصور | 🟡 مرفوعة على Supabase بس لسه مش متوصلة بالمتجر |
| الداشبورد | 🔴 لسه ما اتبنتش |

**يعني إيه:** المتجر بيتصفّح ويشتغل، لكنه **ما يقدرش يبيع لسه**. تعديل سعر أو
منتج من أي مكان **مش هيظهر** على الموقع لأن القراءة لسه من ملف ثابت.

الخطوة الجاية: تبديل مصدر البيانات لـ Supabase، وبعدها API إنشاء الطلب.

## الهيكل

```
zell-store/                      pnpm workspace
├─ apps/
│   └─ storefront/               ← متجر Next.js 15 (App Router) على Vercel
│       ├─ app/                  / · /product/[id] · /cart · /checkout
│       ├─ components/store/     مكوّنات المتجر
│       ├─ components/ui/        Button · Field · Container · ImageSlot
│       └─ lib/
│           ├─ cart.tsx          سلة في localStorage
│           ├─ catalog.ts        ⚠️ كتالوج مؤقت — بيتحذف بعد التبديل
│           └─ data/             طبقة القراءة (server-only)
│
├─ packages/
│   └─ core/                     منطق صافي: تسعير · أنواع · تحقق · صور
│
├─ backend/  frontend/           📦 مرجع قديم — اقرا تحت
└─ docs/                         التوثيق
```

### 📦 `backend/` و `frontend/`

دول سورس **نسخة قديمة من المشروع**، محتفظين بيهم **كمرجع فقط** — مش جزء من
البناء ولا بيتنشروا ولا بيشتغلوا.

بيتسابوا لأن فيهم منطق هيتعاد استخدامه:

| الملف | ليه مهم |
| --- | --- |
| `backend/lib/createOrderSql.ts` | عبارة إنشاء الطلب الذرّية — الأساس لـ `/api/orders` |
| `backend/lib/notifyMessage.ts` | نص إشعار الطلب |
| `backend/admin/*` | منطق الأدمن — مرجع للداشبورد الجاية |
| `backend/db/` | السكيما والـ migrations |

> ⚠️ **منطق التسعير موجود فيهم بنسخ قديمة متفرّقة عن `packages/core`.**
> المرجع المعتمد هو `packages/core/src/pricing.ts`. التفاصيل في `docs/PHASE-1.md`.

## التشغيل محليًا

```bash
pnpm install
pnpm dev      # http://localhost:3000
pnpm build
pnpm typecheck
```

مصدر البيانات بيتحدد من `apps/storefront/vercel.json` على Vercel. محليًا:

```bash
STOREFRONT_DATA_SOURCE=fallback pnpm dev
```

مفيش قيمة افتراضية عن قصد — بناء فاشل أوضح من متجر شغّال بأسعار قديمة.

| الإعداد | القيمة |
| --- | --- |
| المنصّة | Vercel |
| Root Directory | `apps/storefront` |
| Framework | Next.js |
| Install / Build | الافتراضي |

مرئية في المراجعة ومؤرشفة في git.
**الأسرار** في لوحة Vercel بس، وما تدخلش الريبو أبدًا.

## متغيّرات البيئة

| المتغير | المكان | سري؟ |
| --- | --- | --- |
| `STOREFRONT_DATA_SOURCE` | `vercel.json` + CI | لا |
| `SUPABASE_URL` | لوحة Vercel | لا لكن مايتعرضش |
| `SUPABASE_READ_KEY` | لوحة Vercel | 🔒 نعم |
| `SUPABASE_SERVICE_ROLE_KEY` | لوحة Vercel | 🔒 نعم — مؤقت |

**ممنوع تمامًا** أي مفتاح يبقى `NEXT_PUBLIC_`.
الـ service-role حل انتقالي ولازم يتبدل بدور قراءة محدود.

## منطق التسعير

```
سعر الصنف (بالقرش) = round(سعر المتر × الطول بالسنتيمتر ÷ 100)
عدد الشرايح        = ceil(عرض الشباك ÷ عرض الرول)
الطول المطلوب      = الشرايح × ارتفاع الشباك، مقرّب لأعلى لأقرب خطوة
```

الفلوس **بالقرش** والأطوال **بالسنتيمتر** — كلها integer، مفيش كسور عائمة.

لو المقاس المطلوب أكبر من الحد الأقصى، الواجهة بتقول كده **صراحة** وبتمنع
الإضافة للسلة. **ممنوع القص الصامت للحد الأقصى.**

> السعر اللي بيتحصّل بيه بيتحسب في **الداتابيز** داخل عملية ذرّية.
> أي رقم جاي من المتصفح بيتجاهل تمامًا.

## قاعدة البيانات

Supabase (PostgreSQL). الجداول: `products` · `orders` · `order_items` ·
`settings` · `product_images` · `site_images` · `storage_orphans`.

الصور في Supabase Storage (bucket: `product-images`). الداتابيز بتخزّن
**`object_path`** مش الرابط الكامل — الرابط بيتركّب في `packages/core/src/imageUrl.ts`.

RLS مفعّل على كل الجداول.

## قواعد متفق عليها

1. **ممنوع أي أسرار في الريبو** — ولا في الكود ولا اللوجات ولا الـ commits.
2. **ممنوع تعديل على Production من غير موافقة صريحة** — ولا SQL ولا RLS ولا صور.
3. **ممنوع force-push على `main`** — فروع قصيرة و squash merge عادي.
4. **كل مرحلة في كوميت منفصل** بعد ما CI يعدّي.
5. **إنشاء الطلب يفضل معطّل** لحد ما الـ API يتراجع ويتوافق عليه.
6. **الفشل الصريح أفضل من الصمت** — متجر فاضي أو سعر قديم أخطر من بناء فاشل.
