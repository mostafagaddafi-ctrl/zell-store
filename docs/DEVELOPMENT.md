# التطوير

إزاي تضيف ميزة من غير ما تكسر حاجة.

الوثيقة دي بتوصف حالة النظام الحيّ وقت آخر تحديث ليها. لمعرفة النسخة
بالظبط، راجع تاريخ Git للملف ده.

---

## التشغيل محليًا

    pnpm install
    pnpm dev                          # المتجر على 3000
    pnpm --filter @zell/admin dev     # اللوحة على 3001
    pnpm typecheck                    # الاتنين

### المتغيرات المحلية

المتجر محتاج `STOREFRONT_DATA_SOURCE` **صريح** — مفيش قيمة افتراضية:

    STOREFRONT_DATA_SOURCE=fallback pnpm dev

اللوحة محتاجة `.env.local` من `apps/admin/.env.example` (أسماء بس، مفيش
قيم في الريبو). من غير `SUPABASE_ANON_KEY` الدخول هيرجّع
`/login?error=unavailable`.

## إضافة ميزة بأمان — تمان خطوات

الترتيب ده مش بيروقراطية؛ كل خطوة بتمنع نوع فشل اتصادفنا بيه فعلًا.

### ١. اتأكد من عقد البيانات الأول

**اقرا السكيما الحقيقية، متفترضهاش.** أمثلة حقيقية من المشروع ده:

- `adminData.ts` كان مكتوب فيه إن `internal_notes` و
  `shipping_disabled_governorates` مش موجودين — **الاتنين كانوا موجودين**
  وطبقة القراءة كانت بتقراهم صح. التعليق بس كان قديم.
- `order_items.length_cm` و `width_cm` `NOT NULL` — يعني صنف بيتباع
  بالقطعة **ماينفعش يتخزّن** دلوقتي. ده بيكتشف بقراءة القيود مش بالتخمين.

    select column_name, is_nullable, column_default
    from information_schema.columns
    where table_schema='public' and table_name='...';

    select conname, pg_get_constraintdef(oid)
    from pg_constraint where conrelid='public....'::regclass;

### ٢. اكتب تنفيذ السيرفر والتحقق

- `import 'server-only'` في أول أي ملف بيلمس مفاتيح
- التحقق **بيطابق** قيود الداتابيز، عشان الرفض ييجي برسالة عربية من
  التطبيق مش برسالة قيد من Postgres ماينفعش تتعرض
- **ممنوع القص الصامت** — أي قيمة برّه الحد بترفض `VALIDATION`
- النصوص الاختيارية الفاضية بتتحوّل `null` مش نص فاضي

### ٣. دالة ذرّية لو أكتر من صف أو مفتاح بيتغيّر

لو العملية بتلمس أكتر من صف، `GET` ثم `UPSERT` **مش كفاية** — في نافذة
سباق بين الفحص والكتابة. اكتب دالة `zell_*` بتقفل وتفحص وتكتب في معاملة
واحدة.

### ٤. سيبها ورا علم الجاهزية

كل Action بتنادي `guardMutations()` **بعد** `requireAdminAction()`.
فالكود يتدمج ويتراجع وهو مش قابل للوصول.

### ٥. اربط الواجهة في مرحلة منفصلة

السيرفر والواجهة في PR-ين. السبب: ربط واجهة بكود لسه ما اتراجعش معناه
مراجعة الاتنين مع بعض، والمراجعة بتضعف.

⚠️ **زرار شغّال بيعمل لا شيء أخطر من زرار معطّل.** لو `onSave` مش متمرر،
`SaveBar` بيتعطّل برسالة «الحفظ لسه ما اتعملش» — لأن ده حصل فعلًا: صفحة
الإعدادات كانت بتعرض زرار حفظ شغّال وبيعمل لا شيء بعد فتح العلم.

### ٦. شغّل CI بـ frozen lockfile

`ci.yml` بيعمل `pnpm install --frozen-lockfile`. أي اختلاف بين
`package.json` و `pnpm-lock.yaml` = بناء فاشل.

### ٧. اختبر على بيانات مخفية

منتج مخفي أو سجل مش للزباين. **ممنوع** تختبر على المنتجات النشطة.

### ٨. انشر مرة واحدة واتأكد

مش كوميت ورا كوميت — شوف حصة النشر تحت.

## الفروع والـ PR والـ CI

| | |
| --- | --- |
| الفروع | قصيرة، من `main` |
| الدمج | **squash merge** عادي |
| `main` | **ممنوع force-push** |
| CI | `install → typecheck core → typecheck storefront → build storefront → typecheck admin → build admin` |
| صلاحيات CI | `contents: read` — مفيش نشر ولا وصول لداتابيز |

⚠️ **CI بيشتغل على `pull_request` و `push: main` بس.** دفع فرع من غير PR
**مابيشغّلش** CI.

البناء في CI **من غير أي مفاتيح**، وده مقصود: كل الصفحات
`force-dynamic` فمفيش قراءة وقت البناء.

---

## ⚠️ قلّل الكوميتات المرفوعة

كل push ممكن يستهلك نشرة من حصة Vercel، **ومشروعين بيتبنوا من نفس الريبو**.

ده حصل فعلًا: الحصة خلصت والنشر اتقفل ٢٤ ساعة، فنشرات أصلية اتأجلت.

**ساعد نفسك:**

- اجمع التغييرات في كوميت واحد قبل الـ push
- اضبط Ignored Build Step لكل مشروع:

      bash scripts/vercel-ignore-build.sh admin
      bash scripts/vercel-ignore-build.sh storefront

- السكربت موجود وبيدعم الاتنين. وهو **بيقلّل البناءات مش عدد النشرات** —
  الحل الحقيقي هو كوميتات أقل.

## إضافة اعتمادية

`--frozen-lockfile` معناها إن `package.json` لوحده مايكفيش. محتاج lockfile
حقيقي.

**لو تقدر تشغّل pnpm محليًا:** `pnpm install` واكومِت `pnpm-lock.yaml`. خلاص.

**لو مش بتقدر** — الطريقة المؤقتة:

1. فرع فيه تعديل `package.json` بس
2. `.github/workflows/lockfile.yml`: `workflow_dispatch` بس، مقيّد بالفرع
   ده، `contents: write`، **pnpm 9.15.4 و Node 20** (لازم يطابقوا `ci.yml`
   وإلا الـ lockfile مش هيعدّي `--frozen-lockfile`)
3. `pnpm install --lockfile-only` وكوميت الـ lockfile على نفس الفرع
4. **شيل الـ workflow في كوميت منفصل** — الفرع المدموج مايوصلش `main` وفيه
5. squash merge

`ci.yml` **ما بيتلمسش** في الطريقة دي.

### قبل ما تضيف اعتمادية

| اسأل | ليه |
| --- | --- |
| فيها binary؟ | بتكسر البناء على بيئات مختلفة |
| بتشتغل في المتصفح؟ | `image-size` مثلًا بتستورد `fs` — سيرفر بس |
| بتفك ضغط مدخل المستخدم؟ | باب decompression bomb |

## الأخطاء المتكررة

| الخطأ | الصح |
| --- | --- |
| مكوّن عميل بيستورد قيمة من `adminData` | `import type` بس — الملف بيستورد `server-only` |
| `Uint8Array` لـ `fetch` أو `crypto.subtle` | `Uint8Array<ArrayBuffer>` — النوع بقى generic من TS 5.7 |
| `DELETE` ناجح = الصف اتمسح | `DELETE` ممكن يأثّر على **صفر صفوف** — اتأكد من العدد |
| `cache()` على قرار صلاحية | ضمان أداء مش ضمان أمان — نطاقه سياق React مش حدود الطلب |
| `Partial<T>` لعملية بتكتب كل المفاتيح | عقد غلط — العملية بتكتب الكل |
| thunk بيقفل على `draft` | «حاول تاني» بتبعت نسخة قديمة — اقرا من `ref` |
