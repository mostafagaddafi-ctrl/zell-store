# الأقسام

بتوصف ميزة الأقسام بعد `0012`. لمعرفة النسخة بالظبط، راجع تاريخ Git للملف ده.

## القسم

| | |
| --- | --- |
| الاسم | مطلوب، لحد ٨٠ حرف |
| الوصف | اختياري، لحد ٢٠٠ حرف |
| الرابط المختصر | `/collection/<slug>` — تغييره لقسم موجود بيطلب تأكيد صريح |
| صورة الغلاف | اختيارية. من غيرها المتجر بيعرض أول صورة لأول منتج ظاهر في القسم |
| المنتجات | مرتّبة جوه القسم، والمنتج ينفع يبقى في أكتر من قسم |

## الظهور — مفتاحين مستقلين

| `show_on_home` | `show_in_nav` | النتيجة |
| --- | --- | --- |
| ✅ | ✅ | الرئيسية + الهيدر وقائمة الموبايل + صفحة القسم |
| ✅ | ❌ | الرئيسية بس، بكل منتجاته ومن غير «شوف الكل» (مالوش صفحة) |
| ❌ | ✅ | الهيدر وقائمة الموبايل + صفحة القسم |
| ❌ | ❌ | مخفي بالكامل |

القسم الفاضي مابيظهرش حتى لو مفعّل: مفيهوش منتجات، أو كل منتجاته متوقفة.
اللوحة بتكتب السبب (`apps/admin/lib/collectionStatus.ts`) بنفس قاعدة المتجر
(`toStoreCollections`). إيقاف منتج بيخفيه من أقسامه والربط بيفضل محفوظ.

## الترتيب

- القسم الجديد بيبدأ **أول** القائمة — `zell_create_collection` بيزحزح الباقي في نفس المعاملة.
- بعد كده الترتيب في إيد الأدمن. مفيش أولوية محجوزة لأي قسم.
- نفس الترتيب في الرئيسية والتنقل، وكل مكان بيحترم مفتاحه.

## التنقل

- الموبايل: كل أقسام القائمة جوه الـ drawer.
- الديسكتوب: لحد ٤ بيظهروا كلهم. لو أكتر: أول ٣ + «كل الأقسام (n)» لصفحة `/collections`.

## الغلاف

- ضغط WebP في المتصفح، ولو فشل بيترفع الأصل.
- السيرفر بيتحقق من البايتات (JPEG/PNG/WebP)، الحجم (٥ ميجا)، والأبعاد (أقل ٦٠٠×٣٠٠، أقصى ضلع ٨٠٠٠) — إلزامي.
- المسار من السيرفر: `collections/<id>/<uuid>.<ext>`، ومقيّد بقيد في الداتابيز.
- الاستبدال والشيل والحذف بيسجّلوا الملف القديم في `storage_orphans` (`replaced` / `removed`) جوه نفس المعاملة.

## ترتيب الإطلاق — ملزم

1. `0012` على الداتابيز — إضافة بس، النسخة المنشورة مابتتأثرش.
2. بعدها بس: دمج الكود. الكود الجديد بيقرا أعمدة `0012`، فـ Preview قبل الـ migration متوقع يفشل.
3. لاحقًا: migration تشيل `is_visible`. لحد ساعتها اللوحة بتكتبه `= show_on_home or show_in_nav`.
