# المرحلة ٢ — نطاق المتجر فقط

## حدود المسؤولية

**في نطاقي:** واجهة المتجر والتصميم المتجاوب · معمارية `apps/storefront` ·
تجربة السلة والـ checkout · التوافق مع Vercel · **عقود الأنواع** للسيرفر والـ API.

**خارج نطاقي تمامًا (مساحة عمل تانية):** Supabase Storage · رفع الصور ·
جداول الصور · SQL على Production · RLS والسياسات · تكامل service-role.

الكوميت ده ما لمسش أي حاجة من القايمة التانية.

## اللي اتعمل

### ١) فاصل مصدر البيانات

الصفحات بقت تنادي `lib/data/source.ts` بدل ما تستورد الـ fallback مباشرة.

```
قبل:  page.tsx ──► lib/catalog.ts (fallback)
بعد:  page.tsx ──► lib/data/source.ts ──► fallback | supabase
```

مفتاح واحد بيتحكم في المصدر:

```ts
const DATA_SOURCE: DataSource = 'fallback'
```

🔒 **مقفول على `fallback`.** تبديله مسؤولية مشتركة ومحتاج موافقة صريحة،
وبيفترض إن طبقة القراءة جاهزة من الطرف التاني.

لو اتبدّل من غير طبقة جاهزة، الدالة **بترمي خطأ** ومابترجعش مصفوفة فاضية —
فشل صريح أحسن من متجر بيعرض صفر منتجات من غير ما حد ياخد باله.

### ٢) عقد الأنواع

`lib/data/mappers.ts` بيحدد الشكل اللي المتجر متوقعه:

| الدالة | من | لـ |
| --- | --- | --- |
| `toStoreProducts` | `ProductRow[]` | `StoreProduct[]` |
| `toStoreSettings` | `SettingRow[]` | `StoreSettings` |

الملف **مالوش أي اتصال بقاعدة بيانات ومش بيتنادى من أي مكان**. موجود عشان
الطرف اللي بيجهّز القراءة يعرف يسلّم إيه بالظبط.

**قيد أمني مضمّن:** `toStoreSettings` بيقبل المفاتيح العامة بس
(`PUBLIC_SETTING_KEYS`) وبيتجاهل أي مفتاح غيرها. يعني حتى لو الاستعلام
رجّع `notify_email` أو `telegram_bot_token` بالغلط، **مش هيوصلوا للمتصفح**.

### ٣) تحسين UI

زرار «تأكيد الطلب» المعطّل كان لسه شكله قابل للضغط في الوضع الداكن
(شفافية ٥٠٪ بس). بقى بياخد سطح خافت ونص باهت.

## اللي **ما** اتعملش

- مفيش اتصال بـ Supabase — ولا حزمة ولا استعلام ولا رابط.
- مفيش أي مفتاح أو سر في الكود أو الريبو أو اللوجات.
- **إرسال الطلب لسه معطّل** — `CheckoutForm.tsx` ما اتغيّرش خالص.
- مفيش `/api/orders`.
- مفيش صور ولا Storage ولا migrations ولا SQL.
- مفيش اعتماديات جديدة — `pnpm-lock.yaml` ما اتغيّرش.

## متغيّرات البيئة

**مفيش أي متغيّر مستخدم في الكوميت ده.** لما القراءة تتربط، الأسماء المتوقعة
(القيم تتحط في لوحة Vercel مباشرة، ومتدخلش الريبو أبدًا):

- `NEXT_PUBLIC_SUPABASE_URL`
- `SUPABASE_ANON_KEY`

مفتاح service-role **مش مطلوب في المتجر** ومش هيتضاف له.

## الملفات المتأثرة

| الملف | التغيير |
| --- | --- |
| `apps/storefront/lib/data/source.ts` | 🆕 فاصل مصدر البيانات، مقفول على fallback |
| `apps/storefront/lib/data/mappers.ts` | 🆕 عقد أنواع، غير مستخدم |
| `apps/storefront/app/page.tsx` | صار async وبينادي الفاصل |
| `apps/storefront/app/product/[productId]/page.tsx` | صار async وبينادي الفاصل |
| `apps/storefront/app/cart/page.tsx` | صار async وبينادي الفاصل |
| `apps/storefront/app/checkout/page.tsx` | صار async وبينادي الفاصل |
| `apps/storefront/components/ui/Button.tsx` | شكل الزرار المعطّل |
| `docs/PHASE-2-STOREFRONT.md` | 🆕 الملف ده |

`lib/catalog.ts` ما اتغيّرش — لسه هو الـ fallback ولسه مؤقت.

## للمراجعة قبل أي خطوة جاية

1. هل عقد الأنواع في `mappers.ts` مطابق للسكيما الفعلية؟ (مش قادر أتحقق — ممنوع عليّ SQL)
2. مين بيسلّم طبقة القراءة، وبأي شكل: دالة سيرفر ولا route؟
3. تصميم `/api/orders` — لسه ما اتكتبش ومحتاج موافقة منفصلة.
