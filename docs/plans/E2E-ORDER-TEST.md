- **(أ) طلبين — اقتراحي:**
  - **T1 المسار الكامل:** إنشاء ← دفعة ← تأكيد ← تجهيز ← شحن ← تسليم مع تحصيل الباقي. **يفضل «اتسلّم»**.
  - **T2 الإلغاء والرد:** إنشاء ← دفعة صغيرة ← تأكيد ← إلغاء ← رد الدفعة كلها. **يفضل «ملغي»** ومدفوعه 0.
  - بيغطي كل بنود الاختبار. العيب: T1 هيفضل طلب «اتسلّم» ومدفوع للأبد (مايتمسحش لأن عليه دفعات)، وهيدخل في أي رقم مبيعات لحد ميزة «علّم كطلب تجربة» (`docs/plans/ERP-PLAN.md`).

- **(ج) طلب واحد يتسلّم وبعدين رد كامل:** زي T1، وفي الآخر رد بالمبلغ كله. بيفضل «اتسلّم» والمدفوع 0 و«فيه رد». مش ملغي.

```sql
begin;
set transaction read only;
select o.order_number, o.status, o.total_piastres, o.confirmation_fee_piastres, o.paid_piastres,
       o.notified_at is not null as notified, o.notify_error,
       (select count(*) from public.order_payments p where p.order_id = o.id and p.kind = 'payment') as payments,
       (select count(*) from public.order_payments p where p.order_id = o.id and p.kind = 'refund') as refunds,
       (select coalesce(sum(case when p.kind = 'payment' then p.amount_piastres else -p.amount_piastres end), 0)
          from public.order_payments p where p.order_id = o.id) as net_paid,
       (select pg_catalog.string_agg(c.operation, ',' order by c.created_at) from public.zell_payment_commands c where c.order_id = o.id) as commands,
       (select pg_catalog.string_agg(e.kind, ',' order by e.id) from public.order_events e where e.order_id = o.id) as events
  from public.orders o
 where o.order_number = '<رقم الطلب>';
rollback;
```
