# نظام إدارة الصور — التصميم (محلي، غير منفّذ)

الهدف: كل صور المتجر (المنتجات، اللوجو، المعرض، الخامات) في **Supabase Storage**،
وإدارتها بالكامل من داشبورد ZELL، من غير ما `service_role` يخرج من الباك إند أبداً.

> الحالة: **تصميم فقط**. مفيش دوال اتكتبت ولا SQL اتنفّذ. `0003` لسه مقترحة.

---

## ١) المبادئ

| # | القاعدة |
| --- | --- |
| 1 | **مصدر الحقيقة = Supabase Storage**. GitHub و`frontend/assets` مش مكان للصور. |
| 2 | الداتابيز بتخزّن **`object_path`** فقط. الرابط العام بيتركّب وقت العرض. |
| 3 | العميل **يشاهد فقط** — قراءة عامة من bucket عام، مفيش أي عملية كتابة من المتصفح. |
| 4 | كل رفع/حذف/استبدال يمرّ بدالة باك إند محدّدة الغرض. **مفيش storage proxy عام.** |
| 5 | `service_role` في مورد Retool فقط — ما يظهرش في استجابة API ولا في الواجهة. |
| 6 | المسار بيتبني في **السيرفر**. أي مسار جاي من العميل يتجاهل تماماً. |
| 7 | الاستبدال: ارفع الجديد ← اربطه ← بعد النجاح احذف القديم. مفيش حذف قبل التأكيد. |
| 8 | الأعمدة القديمة (`products.image_url/images/before_image/after_image`) **تفضل** — قراءة مزدوجة. |

## ٢) البنية في Storage

```
product-images/                      (bucket عام للقراءة، 5MB، jpeg/png/webp/avif)
  products/{product_id}/{uuid}.{ext}      صور المنتج والمعرض الخاص به
  products/{product_id}/ba/{uuid}.{ext}   صور قبل/بعد
  branding/logo-{uuid}.{ext}              لوجو المتجر
  gallery/{uuid}.{ext}                    معرض «شغلنا» العام
  materials/{uuid}.{ext}                  صور الخامات الأصلية
```

- اسم الملف = UUID مولّد في السيرفر → مفيش تصادم ولا تخمين ولا أسماء عربية في المسار.
- المجلد يحدده نوع العملية (enum في الباك إند)، **مش** نص من العميل.

**الرابط العام** = `{SUPABASE_URL}/storage/v1/object/public/product-images/{object_path}`
يتركّب في طبقة واحدة (`lib/core/imageUrl.ts`)، فتغيير المشروع أو إضافة CDN = سطر واحد.

## ٣) المورد المطلوب (خطوة إعداد منك)

مورد **REST API** في Retool باسم `SUPABASE_STORAGE`:

```
Base URL : https://<project>.supabase.co/storage/v1
Headers  : Authorization: Bearer <SERVICE_ROLE_KEY>
           apikey: <SERVICE_ROLE_KEY>
```

الباك إند بينادي المورد ده؛ المفتاح بيفضل جوّه إعداد المورد ومابيتقرأش من الكود
ولا بيترجع في أي response. من غير المورد ده الرفع مستحيل (الشبكة الخارجية مقفولة على الدوال).

## ٤) جدول `product_images` (من `0003`، مع إضافة بسيطة)

الأعمدة المتفق عليها: `product_id`, `bucket`, `object_path`, `kind(gallery|before|after)`,
`alt_text`, `sort_order`, `is_primary`, `width_px`, `height_px`, `bytes`, `content_type`.

**إضافة معتمدة على 0003**: عمود `checksum text` (SHA-256 للملف) — اتضاف للمسودة
مع فهرس فريد `(product_id, checksum)` يمنع رفع نفس الصورة مرتين لنفس المنتج.

### الصور غير المرتبطة بمنتج — `site_images` ✅ معتمد

جدول مستقل في `0006_site_images.sql` (مقترح، غير منفّذ):

```
site_images (
  kind        'logo' | 'gallery' | 'material',
  object_path text,
  sort_order  integer,
  alt_text    text,
  is_active   boolean,
  caption, width_px, height_px, bytes, content_type, checksum
)
```

- لوجو واحد نشط بالكتير (فهرس فريد جزئي).
- `is_active` بيخفي الصورة من غير حذفها من Storage.
- مفاتيح `settings` القديمة (`logo_url`, `gallery`, `materials`) **ماتتحذفش** — قراءة مزدوجة.
- ومعاه `storage_orphans` لتتبّع الملفات اليتيمة.

## ٥) دوال الباك إند المطلوبة (عقود، غير مكتوبة)

كل دالة: تتحقق من المدخلات → تبني المسار → ترفع/تحذف عبر المورد → تحدّث الداتابيز → ترجع نتيجة واضحة.

| الدالة | المدخلات | السلوك |
| --- | --- | --- |
| `admin/images/uploadProductImages` | `productId`, `files[]`, `kind` | تحقق (نوع/حجم/عدد) → رفع كل ملف → إدراج صفوف بـ `sort_order` تالي → أول صورة للمنتج تبقى `is_primary` تلقائياً |
| `admin/images/setPrimary` | `productId`, `imageId` | تحديث ذرّي: إلغاء القديمة وتعيين الجديدة في عبارة واحدة |
| `admin/images/reorder` | `productId`, `imageIds[]` | تحديث `sort_order` دفعة واحدة داخل transaction (يخدم السحب وأزرار «تحريك قبل/بعد») |
| `admin/images/replace` | `imageId`, `file` | **1)** رفع الجديد **2)** تحديث الصف **3)** بعد نجاح الاتنين: حذف القديم. فشل الحذف = تسجيل يتيم |
| `admin/images/delete` | `imageId` | يتحقق من قاعدة «آخر صورة رئيسية لمنتج نشط» أولاً → حذف الصف → حذف الملف |
| `admin/images/setBeforeAfter` | `productId`, `beforeFile?`, `afterFile?` | نفس منطق الاستبدال على `kind='before'/'after'` |
| `admin/images/uploadLogo` | `file` | رفع في `branding/` → تحديث `site_images.kind='logo'` → حذف القديم بعد النجاح |
| `admin/images/uploadSiteImage` | `kind`, `file`, `caption?` | معرض «شغلنا» وصور الخامات |
| `admin/images/listOrphans` *(اختياري)* | — | ملفات في Storage من غير صف مقابل |

### التحقق الإلزامي في كل رفع

```
• الحجم ≤ 5MB (يتفحص فعلياً، مش الرقم اللي جاي من العميل)
• النوع من allowlist: image/jpeg, image/png, image/webp, image/avif
• فحص magic bytes مش الامتداد (JPEG: FF D8 FF، PNG: 89 50 4E 47، WEBP: RIFF…WEBP)
• عدد الصور لكل منتج ≤ 10
• المسار يتبني في السيرفر: products/{id}/{uuid}.{ext}
• productId لازم يكون موجود فعلاً في الداتابيز
```

### مصفوفة الأعطال

| السيناريو | النتيجة المطلوبة |
| --- | --- |
| فشل الرفع | مفيش صف في الداتابيز، رسالة خطأ واضحة |
| نجح الرفع وفشل الإدراج | ملف يتيم → `storage_orphans` |
| نجح الاستبدال وفشل حذف القديم | العملية **ناجحة** + القديم يتسجّل يتيم |
| حذف صف ونجح وفشل حذف الملف | العملية ناجحة + يتيم |

## ٦) واجهة الداشبورد

### تبويب «الصور» جوّه ديالوج المنتج

```
┌─ صور المنتج ──────────────────────────────────┐
│ [ + ارفع صور ]   (سحب وإفلات • حتى 10 صور)    │
│                                                │
│ ┌──────┐ ┌──────┐ ┌──────┐                    │
│ │ ★ 1  │ │   2  │ │   3  │   الرقم = ترتيب العرض │
│ │ صورة │ │ صورة │ │ صورة │                    │
│ │ ⋮    │ │ ⋮    │ │ ⋮    │   ⋮ = قائمة:        │
│ └──────┘ └──────┘ └──────┘     • تحريك قبل     │
│  رئيسية                        • تحريك بعد     │
│                                 • تعيين كرئيسية │
│                                 • استبدال       │
│                                 • نص بديل      │
│                                 • حذف          │
├─ قبل / بعد ───────────────────────────────────┤
│ ┌──────────┐   ┌──────────┐                   │
│ │  قبل     │   │  بعد     │  [استبدال] [حذف]  │
│ └──────────┘   └──────────┘                   │
└────────────────────────────────────────────────┘
```

- **الرفع**: شريط تقدّم لكل ملف، معاينة فورية محلية قبل ما الرفع يخلص.
- **الرئيسية**: نجمة على الكارت؛ ضغطة واحدة، تحديث فوري (optimistic) مع تراجع عند الفشل.
- **الترتيب**: سحب وإفلات **وكمان زرارين نصّيين: «تحريك قبل» و«تحريك بعد»** — ممنوع أسهم يمين/شمال لأن اتجاهها مربك في RTL. الأزرار هي المسار المضمون على الموبايل. الحفظ دفعة واحدة مع تراجع عند الفشل.
  الصورة الأولى بيتقفل عندها «تحريك قبل»، والأخيرة «تحريك بعد»، والترتيب يظهر كرقم (1، 2، 3…).
- **الحذف**: تأكيد، ولو كانت الرئيسية → أول صورة متبقية تبقى رئيسية تلقائياً.
- **نص بديل (alt)**: خانة صغيرة لكل صورة — للوصولية ولاحقاً للـ SEO.

#### قاعدة حماية: آخر صورة رئيسية لمنتج نشط

| الحالة | السلوك |
| --- | --- |
| حذف الرئيسية وفيه صور تانية | يتم، وأول صورة متبقية تبقى رئيسية في نفس العملية |
| حذف **آخر** صورة لمنتج **نشط** | **مرفوض من الباك إند** بكود `ZELL_LAST_PRIMARY_IMAGE`، والواجهة تعرض: «ارفع بديل الأول» أو «اخفي المنتج ثم احذف» |
| حذف آخر صورة لمنتج **مخفي** | مسموح مع تحذير بسيط |
| حذف اللوجو النشط الوحيد | مسموح — المتجر يرجع لاسم ZELL النصي، مع تحذير |
| استبدال الرئيسية | مسموح دائماً — الصورة ما بتقلّش عن واحدة في أي لحظة |

### شاشة «هوية المتجر» في الإعدادات

- اللوجو: معاينة حالية + [تغيير] + شرط PNG شفاف مفضّل.
- معرض «شغلنا»: أزواج قبل/بعد مع وصف، ترتيب بالسحب **وبأزرار «تحريك قبل / تحريك بعد»**، حذف.
- صور الخامات الأصلية: شبكة بسيطة رفع/حذف.
