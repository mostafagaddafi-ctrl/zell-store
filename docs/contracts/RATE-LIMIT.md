## ٢) التصميم — مابيعتمدش على مسار الصفحة
| | المتجر (`zell-store`) | اللوحة (`admin`) — **قرار المالك (§٧-٢)** |
| --- | --- | --- |
| الاسم | `zell-rl-storefront-post` | `zell-rl-admin-post` |
| الشرط | `Method = POST` **و** `Path` **مش** `/api/revalidate` **ومش** `/api/health` | `Method = POST` (أي مسار) |
| يغطّي | الأوردر + الكوبون + **أي** نداء Server Action (التتبّع) على أي مسار وبأي شكل (header أو multipart) | الدخول + كل Server Actions الإدارة + الخروج، على أي مسار |
| العدّ | IP | IP |
| الفترة | 60 ثانية (Fixed Window) | 60 ثانية (Fixed Window) |
| السقف (اقتراح، §٧-١) | **20** | **60** |
| لو عدّى | **429 Too Many Requests** لباقي الفترة | **429 Too Many Requests** لباقي الفترة |

- **ليه «كل POST» مش مسارات:** في المتجر، الـ POST من المتصفح هي التلاتة بس (§١-١)، فـ «كل POST ما عدا اللي سيرفر لسيرفر» بيغطّي التتبّع مهما كان المسار أو الشكل اللي اتبعت بيه الـ Action. و`/api/revalidate` و`/api/health` برّه لأنهم بييجوا من سيرفرات Vercel، وممكن يعدّوا السقف وقت تعديلات كتير.
- **اللوحة (قرار المالك):** «كل POST» بيغطّي الدخول على أي مسار، **بس بيحد كمان عمليات الإدارة**. السقف 60 في الدقيقة واسع لاستخدام إنسان، بس رفع صور كتير مرة واحدة ممكن يقرّب منه، ولو عدّى المالك بيتمنع لحد ما الدقيقة تخلص. **البديل (ب):** مفيش قاعدة للوحة دلوقتي (الحد على الدخول بيبقى على باسورد قوي، وحماية Supabase Auth اللي مش متحقق منها هنا). **البديل (ج)** (قاعدة على `/login` بس) **مرفوض** لأنه مابيغطّيش الـ Action على مسار تاني (§١-١).
- **الإعدادات دي مش في الريبو** (Vercel بس)، فالقاعدة بالحرف هنا وفي الذاكرة، وأي تغيير بعدين = قرار جديد.

## ٣) التنفيذ — في Vercel، كل خطوة بأمر المالك لوحدها
- **مين:** الشات المربوط بـ Vercel (أو المالك من الشاشة)، **بالقيم في §٢ بالحرف**. ممنوع أي تغيير تاني (لا Managed Rulesets، ولا Bot Protection، ولا Attack Challenge Mode، ولا قواعد تانية). **الاستثناء الوحيد:** إعدادات CRS الظاهرة في مسودة `zell-store` الأولى، بقيم مرجع §٣-٤ بالحرف، ولمرة النشر دي بس. ده مش تعديل متعمّد على CRS، ومايتعمّمش على أي مشروع أو نشر تاني.
- **٣-١ قبل الإضافة (قراية بس):** لكل مشروع:
  - اسم المشروع، و**الإعداد الكامل الحالي وإصداره** (version أو ما يقابله) لو متاح. ولو `Config not found`: يتسجّل كده بالظبط.
  - تأكيد إن **429** متاح بالاسم كإجراء لـ Rate Limit على Hobby، وإن الشرط ينفع يتكتب زي §٢: `Method = POST` + **نفي** المسارين (للمتجر).
  - إن الإضافة بتتعمل **كإضافة قاعدة** (مش PUT لإعداد كامل). لو الـ API ماعندهوش غير استبدال الإعداد كله: **وقف وتبليغ**.
  - **وقف وتبليغ** لو: فيه قواعد موجودة، أو 429 مش متاح، أو النفي مش متاح، أو الإضافة محتاجة استبدال الإعداد.
- **٣-٢ المتجر:** إضافة `zell-rl-storefront-post` بس ← قراية الإعداد كله ← **مقارنة بالإعداد قبل**: الفرق الوحيد = القاعدة دي. ويتسجّل **Rule ID** والإصدار الجديد. **لمسودة `zell-store` الأولى:** قراية active قبل النشر مش ممكنة (`Config not found`)، فالمقارنة بتبقى حسب §٣-٤: المسودة قبل الـ Publish = المرجع، وactive بعد الـ Publish = نفس المرجع.
- **٣-٣ اللوحة (لو المالك اختار (أ)):** نفس الخطوات على `zell-rl-admin-post`، بأمر لوحده.
- **اللي بيتسجّل:** المشروع، وRule ID، والإصدار قبل/بعد (لو متاح)، والشرط، والفترة، والسقف، والإجراء، والحالة، ووقت التطبيق، ومصدر كل ده (شاشة أو API). **من غير** رابط اللوحة، ولا توكنات، ولا IPs.

  - **الأمر:** بيحفظ **رمز خروج curl** لكل طلب، و**بيوقف عند أي رمز غير صفر** (حتى لو اتسجّل كود HTTP)، ومابيعيدش. **مفيش أي طلب لخدمة خارجية** (فحص IP الخروج اتشال بعد مراجعة `2c80caa`).
    ```
    start=$(date +%s); for i in $(seq 1 41); do c=$(curl -s -o /dev/null -D /tmp/rl_h.txt -w '%{http_code}' -X POST -H 'Content-Type: application/json' --data '{}' --max-time 10 https://myzill.com/api/coupons/preview); rc=$?; vid=$(grep -i '^x-vercel-id:' /tmp/rl_h.txt | head -1 | sed 's/^[^:]*: *//' | tr -d '\r'); reg=$(printf '%s' "$vid" | cut -d: -f1); mit=$(grep -ci '^x-vercel-mitigated:' /tmp/rl_h.txt); echo "$i rc=$rc $c $reg mitigated=$mit id=$vid"; [ "$rc" -ne 0 ] && break; done; echo "seconds=$(( $(date +%s) - start ))"; rm -f /tmp/rl_h.txt
    ```
  - **بيتسجّل:** لكل طلب: رقمه، ورمز خروج curl، وكود HTTP، وبادئة المنطقة، ووجود `x-vercel-mitigated` (موجود/لأ)، وقيمة `x-vercel-id` (رقم طلب من Vercel، مش IP ولا بيانات عميل). وفي الآخر المدة. **مفيش IP ولا جسم رد.**
  - **أدلة Vercel (قراية بس، من الشات المربوط بـ Vercel، بعد الاختبار):**
    - **(د١) إسناد:** لكل رد `429`: حدث في Firewall **مربوط برقم الطلب ده** (`x-vercel-id`) وبـ **Rule ID** بتاع `zell-rl-storefront-post`. `x-vercel-mitigated` لوحده، أو حدث في نفس الفترة من غير ربط برقم الطلب، مايكفيش.
    - **(د٢) وحدة العدّاد:** دليل من Vercel بيربط **الـ 41 طلب** (بأرقامهم) بـ **نفس مفتاح العدّ ونفس المنطقة** في القاعدة، من غير ما الـ IP يتنشر (مثلًا مفتاح مجزّأ أو معرّف عدّاد). **تقييم القاعدة على الطلبات لوحده مش دليل وحدة عدّاد.**
  - **النتيجة (شروط متنافية؛ أي حالة بتقع في واحدة بس):**
    - **نجاح:** كل الطلبات اللي اتبعتت رمز خروجها صفر، **و**فيه `429` واحد على الأقل مستوفي (د١)، **و**كل الردود غير الـ 429 هي `403` أو `503` (رفض التطبيق). (المدة وعدد المناطق مش شرط هنا، لأن الـ 429 المُسند بيثبت إن القاعدة منعت فعلًا.)
    - **فشل:** كل الـ 41 طلب رمز خروجهم صفر، **و**المدة أقل من 60 ثانية، **و**كلهم رفض التطبيق ومفيش ولا `429`، **و**(د٢) متاح ومستوفي.
    - **غير حاسم:** أي حالة مش «نجاح» ومش «فشل». منها: رمز خروج غير صفر، أو `429` من غير (د١)، أو مفيش `429` و(د٢) مش متاح أو مش مستوفي، أو مدة 60 ثانية أو أكتر من غير `429`، أو كود غير متوقع.
    - **مفيش إعادة ولا زيادة عدد تلقائي** في أي حالة. القرار بعدها للمالك.
  - **ممنوع:** اختبار الحد على `/api/orders` أو التتبّع أو اللوحة.
- **حد الاستنتاج:** نجاح ٤-٣ بيثبت إن القاعدة بتمنع POST على مسار واحد من IP واحد في منطقة واحدة. **ومابيثبتش لوحده** إن كل نداءات الـ Action متغطّية؛ التغطية دي جاية من التصميم (كل POST، §٢) ومن مطابقة الإعداد (§٤-١).

## ٥) الرجوع
- **إيقاف أو مسح القاعدة اللي اتعملت بس، بالـ Rule ID بتاعها، بالخطوات دي بالترتيب:**
  1. تجهيز التغيير المحدد في مسودة، **بأمر المالك**.
  2. مراجعة فرق المسودة كامل (التغيير ده بس، وباقي الإعداد زي ما هو).
  3. الـ Publish **بأمر منفصل**.
  4. قراية active للتحقق (القاعدة متوقفة أو مش موجودة، وباقي قيم السلوك زي ما هي).
- **حدود الرجوع (بعد §٣-٤):** إيقاف أو حذف قاعدة حد الطلبات **بيرجّع أثر القاعدة دي بس**، ومش بالضرورة بيرجّع حالة المشروع قبل أول إعداد (CRS وأي سلوك صاحب أول نشر بيفضلوا).
- **لو ظهرت مشكلة محتملة:** وقف وتبليغ، من غير افتراض إن CRS هو السبب.
- **أي تغيير بعدين في CRS:** تغيير محدد (الفئات والحقول بالاسم)، بخطة ومراجعة وأمر جديد من المالك، ومراجعة فرق المسودة كاملة قبل نشرها. **مفيش تعطيل تلقائي أو شامل لـ CRS، ومفيش ادعاء باسترجاع حالة سابقة مجهولة.**
- **الانتشار مش مضمون فوري**، ورد الـ API لوحده مايكفيش. اللي بيتسجّل بعد الرجوع بالحرف: **«تأكد تعطيل القاعدة في الإعداد، ونجح الاستخدام المرصود؛ اكتمال الانتشار غير مثبت»**، إلا لو فيه دليل إضافي موثّق من Vercel. ومش بنعمل اختبار ضغط عشان نثبته.
- **إمتى:** لو عميل حقيقي اتمنع، أو المالك اتمنع في اللوحة، أو أي مسار تاني اتأثر.

## ٦) برّه النطاق
- رسالة ودودة لما Server Action بتترفض بـ 429: بند كود لوحده بعدين.
- حماية `/api/revalidate` و`/api/health` (السر والمصدر): ملاحظة للبنود الجاية.
- Bot Protection، وAttack Challenge Mode، وJA4، وManaged Rulesets، و**CRS برّه استثناء §٣-٤** (أي تفعيل أو تعديل أو تعطيل).
- **شرط «غير تجاري» في Hobby، واللي بيحصل بعد المليون:** مش محسومين. قرار الخطة للمالك لوحده، والعقد ده مابيثبتش إن Hobby مناسبة.
