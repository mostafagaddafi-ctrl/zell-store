## ١) طلب المالك وقراراته (2026-10-26)
- حذف منتجات التجارب، وميزة حذف دايمة للمستقبل (ومنها لما النظام يتباع لمحل تاني).
- **الحذف للمالك بس** (مش للأدمن).
- **لازم المنتج يكون مخفي الأول** (`is_active = false`) علشان الحذف يتاح.
- المنتج اللي **اتباع قبل كده** (ليه سطر في أي طلب) أو **ليه مخزون** مايتمسحش؛ بيفضل «إخفاء».

## ٣) بيرفض لو (من غير أي تغيير)
| الشرط | الكود |
| --- | --- |
| مش مالك شغّال (الجلسة + `admin_users`) | `45402` (من `zell_order_actor(true)`) |
| المنتج مش موجود | `45501` |
| النسخة اتغيّرت (`updated_at` ≠ المتوقع) | `45502` |
| المنتج ظاهر (`is_active = true`) | `45503` |
| ليه سطر في `order_items` (أي طلب، حتى ملغي أو تجربة) | `45504` |
| ليه مراجع مخزون (`zell_inv_product_has_stock_refs` = true)، أو FK المخزون رفض (`23503`) | `45505` |

- الأكواد `45501`–`45505` مش مستخدمة في أي ملف (آخر كود مستخدم `45434`). CI بيتأكد إنها فريدة.
- **قيود الـ FK هي الحارس الأخير:** `order_items.product_id` (NO ACTION) وFKs المخزون (RESTRICT) بيمنعوا الحذف حتى لو الفحص اتخطّى.

## ٤) الدوال والصلاحيات (migration لوحدها)
- **`zell_product_delete(p_product_id integer, p_expected_updated_at timestamptz) returns jsonb`** — `volatile security definer`، `search_path = ''`. الخطوات: الممثل (`zell_order_actor(true)`) ← قفل صف المنتج `for update` ← النسخة ← الإخفاء ← الطلبات ← المخزون ← تسجيل الصور في `storage_orphans` ← شيل id من `home_products` ← مسح المنتج. بترجّع `{deleted, product_id, images_registered, removed_from_home, addon_links, collection_links}`.
- **`zell_product_delete_preview(p_product_id integer) returns jsonb`** — `stable`، نفس الهوية. قراية بس للكارت: الحالة (مخفي؟) · فيه طلبات؟ · فيه مخزون؟ · عدد الصور والعروض وروابط الإضافات والأقسام · موجود في الرئيسية؟ · `updated_at`.
- **الهوية:** من JWT الجلسة (`authenticated`)، من غير `p_actor`. `EXECUTE` لـ `authenticated` بس، و`anon` و`service_role` و`PUBLIC` صفر.
- **المالك المقترح:** دور جديد `zell_catalog_definer` (NOLOGIN · NOINHERIT · NOBYPASSRLS) بأقل صلاحيات:
  - `SELECT, DELETE` على `products` · `SELECT` على `product_images` (`product_id, bucket, object_path`) · `SELECT` (`product_id`) على `order_items` · `INSERT` على `storage_orphans` · `SELECT, UPDATE` على `settings` (والدالة بتكتب مفتاح `home_products` بس).
  - policies باسم `zell_catalog_definer_*` على الجداول دي بنفس الأفعال بس.
  - `EXECUTE` على `zell_order_actor(boolean)` و`zell_inv_product_has_stock_refs(integer)` (الاتنين داخليين النهارده) — منحة محددة للدور ده بس.
  - **بديل للمراجع:** المالك `zell_order_definer` بنفس المنح بدل دور جديد (أقل SQL، بس بيوسّع دور الطلبات على الكتالوج). **القرار للمراجع.**
- **الـ cascade:** إجراءات الـ FK بتشتغل بصلاحيات مالك الجدول التابع، فالدور مش محتاج `DELETE` على الجداول التابعة. **ده لازم يتثبت في CI** (حذف ناجح بالدور ده بس).
- **`updated_at`:** الحذف مابيعدّلش أي صف تاني غير `settings` (`home_products` بس، والـ `updated_at` بتاعه بيتحدّث).

## ٥) اللوحة
- في صفحة المنتج: كارت «حذف المنتج نهائيًا» **للمالك بس**، وبيظهر بس لما المنتج مخفي. لو ظاهر: سطر «أخفِ المنتج أولًا لإتاحة الحذف».
- الكارت بيعرض نتيجة `preview`: عدد الصور والعروض والأقسام، و«مستخدم كإضافة في N منتج»، و«موجود في الصفحة الرئيسية». لو فيه طلبات أو مخزون: سبب واضح ومفيش زرار.
- الزرار ← حوار تأكيد واحد بالأعداد ← النداء ← بعد النجاح: تحديث المتجر (`/api/revalidate`) ورجوع لقايمة المنتجات.
- النداء بجلسة المستخدم (`createAuthClient`)، من Server Action ملفوف بالصلاحية (`lib/access`) زي باقي اللوحة. مفيش `p_actor` تحت `apps/admin`.
- **نصوص اللوحة الجديدة بالفصحى المبسّطة الرسمية.**
- مفيش capability جديدة في 0021-P: التحقق «مالك بس» في الداتابيز (`45402`) وفي غلاف الأكشن بفئة المالك.

## ٧) CI (لازم قبل أي تشغيل)
- الهوية: مالك = نجاح · أدمن = 45402 · من غير جلسة أو ممثل مزوّر = رفض · `service_role` و`anon` مالهمش EXECUTE.
- كل شرط في §٣ بكوده، ومن غير أي تغيير (بصمة الجداول قبل وبعد).
- حذف ناجح: الصف والتوابع الخمسة اتمسحوا · الصور اتسجّلت في `storage_orphans` (ومسار متسجّل قبل كده مابيتكررش) · id اتشال من `home_products` والترتيب زي ما هو · منتجات تانية وطلبات وإعدادات تانية بصمتها زي ما هي.
- منتج إضافة لفيلم تاني: الربط بيتشال، والفيلم نفسه ماتغيّرش.
- FK كحارس أخير: فحص الطلبات أو المخزون اتشال بشكل مصطنع ← الـ FK بيرفض والمعاملة بترجع كلها.
- التزامن: حذف واتنين في نفس الوقت · تعديل المنتج بين الـ preview والحذف ← 45502.
- الـ cascade بصلاحيات الدور ده بس (§٤).
- rollback: قبل أي حذف بيرجّع الحالة بالظبط؛ وبعد حذف، الرجوع بيشيل الدالتين والدور بس، ومابيرجّعش منتج (محتاج backup).

## ٨) على Production (كل خطوة بموافقة لوحدها)
- blob sha1 + main + الوقت UTC ← استعلام الأثر (baseline) ← backup ← ptest ← تطبيق ← verify ← استعلام الأثر بعد.
- بعد النشر: **المالك هو اللي بيحذف من اللوحة** بنفسه. مفيش حذف من شات التنفيذ.

## ٩) ملاحظة مهمة عن منتجات التجارب
