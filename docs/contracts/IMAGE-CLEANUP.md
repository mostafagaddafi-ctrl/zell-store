## ١) الوضع النهارده (من الكود على `4a58590`)

## ٢) النطاق

## ٣) هوية الملف وفحص المرجع (fail-closed)
**المسار الصالح:** مش فاضي · مايبدأش ولا ينتهيش بـ `/` · **مفيش جزء فاضي** (`//`) ولا جزء `.` أو `..` · مفيش أحرف تحكم ولا `%` ولا `\` · و**هدف الـ DELETE المحسوب = نفس المسار المفحوص بالحرف** (بعد فك ترميز هدف الحذف). أي مسار يتغيّر عند تحويله لهدف الحذف = «متساب: مسار ملتبس»، من غير تصحيح صامت. والـ `bucket` لازم = `imageBucket()`.
**المرشّح:** صف `cleaned_at is null` · `created_at` أقدم من 7 أيام (ساعة السيرفر) · باكت ومسار صالحين.
**مصادر المرجع** (بتتقري كاملة بعد بداية القفل وقبل أي مسح):
- مهيكلة بالزوج (`bucket`، المسار): `product_images` · `site_images` · `collections.cover_*`.
- نصية: أعمدة `products` القديمة (`image_url` · `images` · `before_image` · `after_image`) · `order_items.product_image_url` · كل قيم `settings` · أعمدة النص الحر في `products` و`collections` (الاسم · الوصف · أي نص) · أي مصدر تطلّعه خطوة 0 (يتضاف هنا وفي §٤ بتعديل العقد قبل الكود).
**القواعد:**
1. pagination بمفتاح ثابت ومعاها `exactCount`. المقروء ≠ العدد، أو صفحة فشلت أو خلص وقتها أو خطأ صلاحية = وقف **قبل أي مسح**.
2. المطابقة النصية جزئية (substring) بأي شكل: الخام · ترميز كل جزء · ترميز كامل · **ترميز مختلط** (بيتطبّع بفك ترميز النص المرشّح قبل المقارنة) · الرابط العام بالأشكال دي · الشرطة المهرّبة في JSON. الجزئي = «مستخدم».
3. أي مطابقة مش محسومة = «متساب: غير محسوم».
4. إعادة الفحص قبل كل ملف (نفس القواعد). **فشل أي إعادة فحص في نص التشغيل يوقف أي مسح بعده فورًا**؛ الملفات اللي اتمسحت قبله ماترجعش، وبتتسجّل عادي. «صفر مسح» يخص فشل الفحص الأول بس.

## ٤) القفل المنسّق (B2 = ب)
**ليه:** الحصر من الكود (جدول تحت) بيبيّن إن إعادة ربط مسار قديم ممكنة **بس بإدخال يدوي في نص حر**. القفل بيمنع ده على السيرفر طول فترة التنظيف.

| مسار الكتابة | الملف والأسطر | إعادة ربط؟ |
| --- | --- | --- |
| صورة منتج / متجر / غلاف قسم | `imageUpload.ts:144→162` · `siteImageUpload.ts:192→208` · `collectionCover.ts:106→118` (شيل `:157`، SQL `0012:236`) — المسار `randomUUID` على السيرفر | لأ (في الكود المفحوص) |

| روابط الفوتر وشريط الإعلان | `validation/content.ts:145–149 · 164 · 187` (أي `https://`) | **أيوه، يدوي** |

**الآلية:**
- **صف القفل:** مفتاح `settings` = `image_cleanup_lock` (مش في `PUBLIC_SETTING_KEYS`)، قيمته: `run_id` (uuid من السيرفر) · `actor` (من الجلسة) · `acquired_at` · `scan_not_before` · `start_deadline` · `expires_at` · `state` (`active` · `released`).
- **حد المدة المثبت:** PR الكود بيحط `maxDuration = M` صريح لكل أكشنات اللوحة (Vercel بيقتل أي نداء بعده). لو ده مش ممكن صراحةً = وقف ورجوع للمالك.
- **الكتّاب:** كل Server Action في اللوحة بيكتب `settings` أو نص حر في `products` أو `collections` بيقرا صف القفل **على السيرفر قبل الكتابة**، ولو `state = active` و`now < expires_at` بيرفض بـ «الحفظ متوقف مؤقتًا أثناء تنظيف الصور. حاول بعد دقيقة.» من غير كتابة. (نداءات RPC لإعدادات الدفع بتاخد الفحص قبل النداء بس، من غير أي تغيير في الحساب.) القايمة الكاملة تتحدد في PR الكود، وفحص CI بيرفض أي كتابة على الجداول دي من غير حارس القفل.
- **المرحلة 1 «ابدأ»:** الحجز بتزامن تفاؤلي: صف مش موجود = إدراج (تعارض = مشغول) · موجود = `patchGuarded` على `updated_at` المقروء، **بس لو** `state = released` أو `now ≥ expires_at`. القيم: `scan_not_before = now + M + 5s` (أي كاتب فحص القفل قبل الحجز خلص أكيد) · `start_deadline = scan_not_before + 60s` · `expires_at = start_deadline + M + 5s`.
- **المرحلة 2 «نفّذ»:** بتشتغل **بس** لو الصف `active` وبنفس `run_id` والمالك نفسه، و`scan_not_before ≤ now ≤ start_deadline`. بعد `start_deadline` بترفض (والتشغيل يتساب ينتهي). لأن المرحلة 2 مقتولة بعد `M` من بدايتها، **مفيش حذف ممكن بعد `expires_at`**، فانتهاء القفل مابيدخّلش كاتب والتنظيف لسه شغال.
- **الإنهاء:** آخر المرحلة 2 `patchGuarded` على `updated_at` اللي هي شافته + نفس `run_id` ← `released`. أي تعارض = مايلمسش الصف (**مفيش تشغيل بيشيل قفل تشغيل تاني**)، والقفل بينتهي لوحده عند `expires_at`.
- **التوقف الآمن:** وقوع المرحلة 2 أو فشل الإنهاء = القفل بيفضل لحد `expires_at` بس. مفيش «فك يدوي» من الواجهة.
- `run_id` اللي بييجي من المتصفح للمرحلة 2 للمطابقة بس، والصلاحية من الجلسة والصف.

## ٥) ترتيب التشغيل والوقت (المرحلة 2)
- **الميزانية:** `M` ناقص 10 ثواني. `storageDelete` بمهلة **8 ثواني** للتنظيف (مهلة اختيارية جديدة؛ باقي النداءات زي ما هي)، ومهلة كل قراية REST محددة.
- **قبل بدء أي ملف:** الوقت الباقي أقل من (مهلة المسح + الـ PATCH + قراية التأكيد + 2 ثانية) = وقف، والباقي «للضغطة الجاية».
- **الحدود:** أقصى **1000** صف معلّق للفرز (أكتر = رفض ورسالة إن الحجم محتاج عقد) · أقصى **50** مسح كسقف. الفرز بعد قراية المراجع، فالمستخدم والأحدث والملتبس **مابيحجزوش مكان**. مفيش استكمال تلقائي.
- **قبل الفحص:** تحديث كاش المتجر بآلية «التحديث الفوري» والتأكد من النجاح، **في كل تشغيل**؛ فشل أو إعداد ناقص = وقف قبل أي مسح.
- **لكل ملف:** إعادة الفحص ← `storageDelete` ← `PATCH cleaned_at = now()` بفلتر `id=eq.X&cleaned_at=is.null` ← قراية تأكيد.
- **تشغيلين:** القفل بيمنع مرحلتين 2 في نفس الوقت. لو حصل (مثلًا مرحلة 2 قديمة لسه بتموت)، المسح والـ PATCH بيتكرروا بأمان، والحالات مختبرة.

## ٦) النتائج والتقرير
- «كان مش موجود» = رد Storage صريح بعدم الوجود بس (يتحدد ويتختبر في PR الكود). timeout أو رد مش مفهوم = «فشل».
- PATCH صفر صفوف ← قراية الصف: معلّم = «اتعلّم من تشغيل تاني» · مش معلّم = «اتمسح ومش متعلّم» · القراية فشلت = «غير محسوم». فشل قراية التأكيد بعد نجاح الاتنين = «غير محسوم».
